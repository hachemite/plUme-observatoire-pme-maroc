## 2. Function-Level Call Sequence Diagram

```mermaid
sequenceDiagram
    participant Main as __main__
    participant UH as urlhaus.py
    participant API1 as URLhaus API
    participant VAL as validate.py
    participant TE as ThreatEvent
    participant TAX as taxonomy.py
    participant REPO as repository.py
    participant CSV as threat_events.csv

    Main->>UH: run_pipeline()
    UH->>UH: fetch_urlhaus_feed(url: str = URLHAUS_CSV_URL)
    UH->>API1: requests.get(url, headers, timeout=30)
    API1-->>UH: resp.text: str (raw CSV)
    UH->>UH: pd.read_csv(io.StringIO(...)) -> raw_df: DataFrame
    UH-->>UH: return formatted_df: pd.DataFrame

    UH->>VAL: validate_rows(raw_df: pd.DataFrame)
    loop for idx, row in df.iterrows()
        VAL->>TE: ThreatEvent(**record_dict)
        alt validation succeeds
            TE-->>VAL: event: ThreatEvent
            VAL->>VAL: valid_records.append(event.model_dump())
        else ValidationError
            VAL->>VAL: print("[Validation Warning] Row dropped")
        end
    end
    VAL-->>UH: return validated_df: pd.DataFrame

    UH->>TAX: categorize(validated_df: pd.DataFrame)
    loop for idx, row in df.iterrows()
        TAX->>TAX: check tags_str vs THREAT_KEYWORD_MAP
        TAX->>TAX: fallback raw_tag_str vs THREAT_KEYWORD_MAP
        TAX->>TAX: fallback indicator_str vs THREAT_KEYWORD_MAP
        TAX->>TAX: source-aware default (CAT_DDOS / CAT_MALWARE)
    end
    TAX-->>UH: return categorized_df: pd.DataFrame

    UH->>TAX: severity(categorized_df: pd.DataFrame)
    TAX->>TAX: parse "confidence_N" from tags (abuseipdb only)
    TAX-->>UH: return enriched_df: pd.DataFrame

    UH->>TAX: sector_hint(enriched_df: pd.DataFrame)
    TAX->>TAX: match indicator_value+tags vs sector_map
    TAX-->>UH: return enriched_df: pd.DataFrame

    UH->>REPO: save_events(enriched_df: pd.DataFrame)
    REPO->>CSV: pd.read_csv(DATA_FILE, dtype=str) [if exists]
    CSV-->>REPO: existing_df: pd.DataFrame
    REPO->>REPO: pd.concat([existing_df, df_clean])
    REPO->>REPO: drop_duplicates(subset=DEDUP_COLUMNS, keep="last")
    REPO->>CSV: combined_df.to_csv(DATA_FILE, index=False)

    UH->>REPO: load_events()
    REPO->>CSV: pd.read_csv(DATA_FILE, dtype=str)
    CSV-->>REPO: return df: pd.DataFrame
    REPO-->>UH: return saved_events: pd.DataFrame

    UH->>UH: print(saved_events.head(5).to_string())
    UH-->>Main: None
```

The trace shows exact parameter types flowing between calls — raw `resp.text` strings become `pd.DataFrame` objects that are progressively mutated in place through `.copy()` calls inside `validate_rows()`, `categorize()`, `severity()`, and `sector_hint()`. Note `save_events()` returns `None` (write-only), which is why `urlhaus.py` immediately calls `load_events()` afterward just to print a preview.

Both `run_pipeline()` functions in `urlhaus.py` and `abuseipdb.py` call the exact same four downstream functions in identical order (`validate_rows` → `categorize` → `severity` → `sector_hint` → `save_events`/`load_events`), which is why the two collector subtrees converge onto shared `processing/` and `storage/` nodes rather than duplicating logic. Test files are wired in with dashed edges to show which specific functions each unit test exercises, confirming the 9/9 passing tests map cleanly onto `repository.py`, `taxonomy.py`, and `validate.py`.
