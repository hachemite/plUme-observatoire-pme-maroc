Every collector converges on `storage/repository.py` as the single gatekeeper for `data/threat_events.csv`, enforcing the project's load-bearing rule that no other module touches the CSV directly. Analytics and output modules are currently stubs that will only read from the repository via `load_events()` once later jalons are implemented.

## 2. End-to-End Execution Sequence Diagram

```mermaid
sequenceDiagram
    participant User
    participant URLhaus as collectors/urlhaus.py
    participant AbuseIPDB as collectors/abuseipdb.py
    participant ExtURL as URLhaus API
    participant ExtAbuse as AbuseIPDB API
    participant Validate as processing/validate.py
    participant Taxonomy as processing/taxonomy.py
    participant Repo as storage/repository.py
    participant CSV as data/threat_events.csv
    participant Stats as analytics/stats.py

    User->>URLhaus: python collectors/urlhaus.py
    URLhaus->>ExtURL: GET csv_recent/ (timeout=30)
    ExtURL-->>URLhaus: raw CSV text
    URLhaus->>URLhaus: parse lines, map to ThreatEvent columns
    URLhaus->>Validate: validate_rows(raw_df)
    Validate->>Validate: instantiate ThreatEvent per row
    Validate-->>URLhaus: clean_df (invalid rows dropped + logged)
    URLhaus->>Taxonomy: categorize(clean_df)
    Taxonomy->>Taxonomy: match tags/raw_tag/indicator against keyword map
    Taxonomy-->>URLhaus: categorized_df
    URLhaus->>Taxonomy: severity(categorized_df)
    URLhaus->>Taxonomy: sector_hint(enriched_df)
    Taxonomy-->>URLhaus: enriched_df
    URLhaus->>Repo: save_events(enriched_df)
    Repo->>CSV: read existing rows (if any)
    Repo->>Repo: concat + drop_duplicates(dedup key)
    Repo->>CSV: write combined_df
    URLhaus->>Repo: load_events()
    Repo->>CSV: read_csv
    CSV-->>Repo: DataFrame
    Repo-->>URLhaus: saved_events
    URLhaus-->>User: print preview + row count

    User->>AbuseIPDB: python collectors/abuseipdb.py
    AbuseIPDB->>ExtAbuse: GET /blacklist?limit=100 (API key header)
    ExtAbuse-->>AbuseIPDB: JSON data
    AbuseIPDB->>AbuseIPDB: map JSON fields to ThreatEvent columns
    AbuseIPDB->>Validate: validate_rows(raw_df)
    Validate-->>AbuseIPDB: clean_df
    AbuseIPDB->>Taxonomy: categorize() / severity() / sector_hint()
    Taxonomy-->>AbuseIPDB: enriched_df
    AbuseIPDB->>Repo: save_events(enriched_df)
    Repo->>CSV: dedup + write
    AbuseIPDB-->>User: print preview + row count

    Note over Stats: Jalon 2+ (not yet implemented)
    Stats->>Repo: load_events()
    Repo->>CSV: read_csv
    CSV-->>Repo: DataFrame
    Repo-->>Stats: full dataset
    Stats-->>User: counts/day, category breakdown
```

Both collectors follow an identical fetch → validate → categorize/enrich → save pipeline, converging on the same `save_events()` call that performs deduplication before writing to CSV. The `analytics/stats.py` step is shown as a stub interaction since it is not yet implemented per the AGENT.md jalon sequencing.

## 3. Core Data Processing State Diagram

```mermaid
stateDiagram-v2
    [*] --> Fetched: HTTP GET (URLhaus CSV / AbuseIPDB JSON)

    Fetched --> RawParsed: pandas DataFrame constructed,<br/>columns mapped to ThreatEvent schema

    RawParsed --> Validated: validate_rows()<br/>ThreatEvent(**row) succeeds
    RawParsed --> Dropped: ThreatEvent(**row) raises ValidationError<br/>(missing indicator_value, bad type, etc.)
    Dropped --> [*]: logged, excluded from batch

    Validated --> Categorized: categorize()<br/>keyword match on tags → raw_threat_tag → indicator_value<br/>else source-aware default

    Categorized --> Enriched: severity()<br/>abuseConfidenceScore bucketed (abuseipdb only)<br/>+ sector_hint() keyword match

    Enriched --> Deduplicated: save_events()<br/>drop_duplicates(indicator_value, source, date_added)<br/>keep="last"

    Deduplicated --> Persisted: written to data/threat_events.csv

    Persisted --> Loaded: load_events()<br/>read_csv into DataFrame

    Loaded --> Correlated: analytics/correlate.py [Jalon 3+, stub]<br/>cross-source dedup (URLhaus + AbuseIPDB)

    Loaded --> Aggregated: analytics/stats.py [Jalon 2, stub]<br/>counts/day, category breakdown

    Correlated --> [*]
    Aggregated --> [*]
```
